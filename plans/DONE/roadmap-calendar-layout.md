# Roadmap calendar layout

PM-MCP: #966
Статус: реализовано 2026-06-15, проверки пройдены

## Контекст

`/roadmap` уже реализован как React/Vite island по ADR-0013 и использует
`planned_at` как основной временной якорь по ADR-0022. Текущая проблема в том,
что фронтенд раскладывает задачи по lane проекта/цели, а заголовок времени
рисуется отдельным overlay. Поэтому задачи с датой не выглядят привязанными к
столбцу этой даты, а даты не двигаются вместе с холстом.

## Цель

Сделать `/roadmap` похожим на календарь: горизонтальная временная ось,
столбцы дней/недель/месяцев/лет, задачи внутри своего периода на всю ширину
столбца, без пересечений, с drag-reschedule между периодами и popover-формами
просмотра/создания.

## Ограничения

- Стек не менять: FastAPI/Jinja + React/Vite island + `@xyflow/react`.
- PM-MCP остаётся source of truth для задач, дат, истории и связей.
- Design-system: цвета/типографика через MD3 tokens, shared layer не трогать.
- Существующий функционал связывания задач через боковые handles сохранить.
- PM-MCP `list_work_items` пока не поддерживает server-side фильтр по
  `planned_at`, поэтому полная lazy-load пагинация задач требует отдельного
  контрактного расширения PM-MCP.

## Этапы

1. Перестроить frontend layout в календарную сетку: период → колонка,
   задача/событие → вертикальный слот внутри колонки.
2. Сделать заголовки дат частью движущегося canvas, чтобы они панорамировались
   вместе с задачами.
3. Ограничить основное перемещение горизонтальной временной осью и оставить
   вертикальную область как список элементов периода.
4. Заменить правую inspector-панель на popover задачи/события и popover
   создания по клику в пустую область периода.
5. Сохранить drag-reschedule через `PATCH /api/roadmap/tasks/{id}` и улучшить
   выбор сторон edge handles по относительному положению карточек.
6. Добавить bounded window/cache на frontend и передавать календарный
   `time_min/time_max` в `/api/roadmap`; задачи временно фильтровать из
   текущего open-task payload на стороне Assistant-UI.
7. Обновить tests/docs, собрать island и выполнить frontend verification.

## Критерии приёмки

- Дата карточки совпадает с колонкой, где она отображается.
- При pan/scroll заголовки дат и карточки двигаются синхронно.
- Карточки задач занимают ширину периода и не накладываются друг на друга.
- Клик по пустой колонке открывает форму создания с автозаполненным
  `planned_at`.
- Клик по задаче открывает popover с деталями, датами и историей.
- Drag задачи в другой период сохраняет новый `planned_at`.
- Связи между задачами/целями остаются доступными через handles.
- Проверки: `npm run build`, `uv run ruff check .`, `uv run pytest`,
  `uv run python scripts/verify_frontend.py --page roadmap`.

## Результат

- `/roadmap` переведён на календарную раскладку с колонками день/неделя/месяц/год.
- Заголовки периодов стали node-слоем React Flow и двигаются вместе с карточками.
- Карточки задач/целей/событий раскладываются внутри периода вертикальным стеком без пересечений.
- Сохранены боковые handles и drag-reschedule задач через `planned_at`.
- Правая панель заменена popover просмотра; клик по пустой области периода открывает popover создания.
- `/api/roadmap` принимает `time_min/time_max`, ограничивает календарное окно и fail-open отвечает при таймауте PM-MCP.
